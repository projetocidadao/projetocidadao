# Incidente: 502 Bad Gateway por instalador quebrado em `redis_stats.py`

**Data:** 2026-09-10
**Severidade:** 🔴 Alto (site fora do ar)
**Duração do impacto:** ~30 minutos
**Issue:** (não aberta — corrigido em live debugging)
**Commit do fix:** [`41a9d4a`](https://github.com/projetocidadao/projetocidadao/commit/41a9d4acedecd0f6d9877bd70a24dab970e507ea)

## Resumo

O site do Projeto Cidadão ficou fora do ar por aproximadamente 30 minutos
após a descoberta de que o arquivo `backend/src/api/redis_stats.py` era um
**instalador quebrado** sendo importado como se fosse um endpoint pela
aplicação principal (`main.py`). O instalador nunca tinha sido executado com
sucesso, mas seu código era carregado pelo Python no boot da API, causando
`TypeError` e derrubando o container em loop.

## Linha do tempo

| Hora | Evento |
|---|---|
| ~18:50 | Usuário reporta erro 502 Bad Gateway no site |
| ~18:55 | Diagnóstico inicial: nginx up, backend down |
| ~19:00 | Logs do `pc_api` revelam `TypeError: unsupported operand type(s) for +: 'PosixPath' and 'str'` |
| ~19:05 | Identificada causa: `redis_stats.py` era instalador, não endpoint |
| ~19:10 | Fix aplicado direto no container via `docker exec` |
| ~19:15 | API sobe, mas nginx ficou desyncado |
| ~19:20 | `docker restart pc_nginx` realinha nginx com backend |
| ~19:25 | Site no ar, endpoint `/api/redis-stats` funcional |

## Causa raiz

O arquivo `redis_stats.py` foi upado para o container (provavelmente por um
instalador S3 antigo) como um **script instalador** que deveria:

1. Criar o arquivo do endpoint
2. Fazer patch em `main.py`
3. Atualizar `__init__.py`

Mas ele nunca foi executado com sucesso porque tinha **3 bugs**:

1. **Linha 15**: `API_DIR / UND_INIT + ".py"` — em Python, `Path + str` não
   existe. O correto seria `API_DIR / (UND_INIT + ".py")` ou
   `(API_DIR / UND_INIT).with_suffix(".py")`.
2. **Indentação quebrada**: o bloco que faz patch em `__init__.py` estava
   fora da função `main()`, rodando no import time.
3. **`if _name_ == "_main_":`** com underscores únicos (saga dos underscores
   continua — ver issue #7).

O `main.py` fazia `from src.api import ... redis_stats`, o que fazia o Python
**executar o instalador no boot** ao invés de importar um endpoint. Crash
imediato.

## Fatores contribuintes

- Instalador S3 injetou arquivo não testado direto no container
- `main.py` foi patcheado para importar `redis_stats` sem validar se o arquivo
  era realmente um endpoint
- Não havia teste de import no CI (só ruff + black + pytest, mas pytest não
  sobe a app)
- Saga dos underscores (issue #7) mostrou que arquivos injetados por script
  tendem a ter underscores duplos corrompidos

## O que deu certo

- Diagnóstico rápido: logs do container mostraram o traceback exato
- Fix direto no container via `docker exec` restaurou o site em minutos
- Nginx restart realinhou o proxy com o backend
- Fix permanente commitado no GitHub em seguida

## O que deu errado

- Instalador não foi testado antes de ser injetado
- Não havia guard que validasse se `redis_stats.py` era endpoint ou instalador
- Nginx ficou unhealthy e não se recuperou sozinho após backend voltar

## Ações preventivas

- [ ] Adicionar step no CI que faz `python -c "from main import app"` para
  validar imports antes do deploy
- [ ] Padronizar que instaladores vivam em `scripts/` e não em `src/api/`
- [ ] Configurar restart automático do nginx quando backend fica healthy
- [ ] Documentar padrão de uso de `chr(95)` para underscores duplos em
  arquivos gerados por script (skill `/dunder_fix`)

## Lições

1. **Instalador ≠ endpoint**: scripts que criam/modificam código não devem
   viver em `src/` onde podem ser importados acidentalmente.
2. **Path + str não existe**: em Python, `Path / str` retorna `Path`, mas
   `Path + str` levanta `TypeError`. Sempre concatenar strings antes de
   passar para `Path /`.
3. **Underscores duplos continuam assombrando**: a saga dos `_tablename_`
   (issue #7) se repete em `_name_` / `_init_`. Solução permanente é usar
   `chr(95) * 2` em código gerado por script.
4. **Nginx não se recupera sozinho**: quando backend reinicia, nginx pode
   ficar com conexões órfãs e precisar restart manual.
5. **CI não valida imports**: ruff + black + pytest não pegam erros de import
   que só manifestam no boot da app.
